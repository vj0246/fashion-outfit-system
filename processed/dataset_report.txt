-- Known data-quality issues / challenges --
- Only 68 unique products / 25 outfits: too small for training any
  deep model from scratch. Forces a frozen-embedding + rule/graph
  hybrid approach rather than end-to-end learning.
- DATA BUG: wear_type should be western/ethnic only, but 30 rows have it overwritten with their own category-type ('footwear'/'accessory') instead of a real style label. wear_type is NOT trustworthy for footwear/accessory rows -- treat as 'unknown' (neutral score) rather than a genuine western/ethnic mismatch downstream.
- No structured color/baseColour field on products.csv. Color only
  exists as free text inside `description` (e.g. 'White solid...',
  'Dark grey sweatshirt...'). Color compatibility extracted via
  keyword matching against a vocabulary built from outfits.csv's
  `palette` field (data-driven, not invented color theory).
- rating missing on 25/68 items, rating_count missing on 42/68 -> not usable as a ranking signal, dropped.
- Outfits have variable composition (3-5 items): some skip 'second'
  (one-piece hero), most skip 'accessory_2'. Pipeline must treat slots
  as optional, not fixed-length.
- Only 2 genders represented (men/women); no unisex/non-binary
  category — recommendation logic inherits this binary split.
- 3 source sites (ajio/myntra/nykaa) -> inconsistent description style
  per site, handled by relying on embeddings over raw text patterns.
